# 배송 기억

이 파일을 먼저 읽고 이어서 작업한다. 중요한 결정·운영 방식은 여기에 짧게 남긴다.

## 지금 쓰는 방식

- 사람은 **배송견적 화면**(`배송/index.html`)에 로그인해서 견적문의·제원·최종저장을 한다. (대표님·팀장님 모두 견적 기능 동일. 팀장님만 대표님 계정·시트 복기)
- 화면 ↔ 구글시트 다리는 **Apps Script 웹앱**(`배송/apps-script/`)이다.
- 데이터는 구글시트 **배송견적** 하나에만 쌓인다. 사본·시험용 시트를 새로 만들지 않는다.
- 관리자 아이디는 `admin` 고정. 비밀번호는 화면의 「관리자 등록」에서 직접 정한다. GitHub·문서에 비밀번호를 쓰지 않는다.
- 대표님은 화면의 「새 계정 만들기」로 등록한다. (아직 미등록이면 나중에 한다.)
- 채팅으로 견적만 물어볼 때의 계산·복붙 틀은 `지침.md`를 따른다. 시트 저장은 화면·웹앱이 한다.

## 꼭 지킬 것

- **수고비는 넣지 않는다.** 구간 수고비·추가 수고비(적재, 외곽, 세팅 등) 모두 금지.
- 견적 결과 문장·비밀번호는 GitHub에 올리지 않는다. 코드·지침·기억만 GitHub다.
- 예전 시트 **배송견적 기록**(휴지통)은 쓰지 않는다. 주소를 다시 살리지 않는다.
- 웹앱 `/exec` 주소를 바꿀 때 새 배포를 함부로 만들지 않는다. 기존 배포를 새 버전으로 업데이트한다.
- 근퇴 Apps Script·근퇴/급여/식자재 폴더는 배송 작업에서 건드리지 않는다.

## 2026-11-21 이어서 볼 상태

클로드·Codex·다른 AI는 이 절을 먼저 읽고, 아래 최근 결정의 예전 줄보다 이 절을 따른다.

- 공개 배송 화면 https://joogrowth.github.io/yosulson/배송/ 에 버튼 **네이버 캘린더 등록**이 있다. 글자는 아직 사용자가 확정하지 않았다. 견적의뢰는 복사·카톡 공유 아래, 견적완료는 견적의뢰로·작성중으로 아래다. 예전 건을 열어도 버튼이 있고, 누른 그 건만 올라간다.
- 대표님 아이디와 admin 모두 누른다. 대표님은 네이버에 로그인하지 않는다. 일정은 요술손 일정(26년)에만 넣는다. 내 캘린더는 시험 1건이었고 다시 넣지 않는다.
- 캘린더 번호는 스크립트 속성 `NAVER_CALENDAR_ID`에만 둔다. 이 파일과 GitHub에 적지 않는다. 값이 없거나 `defaultCalendarId`면 넣지 않는다.
- 제목란에만 글을 넣는다. 시간·장소·메모 칸은 비운다. 글은 제목, 일자, 출발, 도착, 행사시간, 장소, 담당자다. 금액·최종 견적 글은 넣지 않는다. 같은 건을 다시 누르면 그 일정을 고친다.
- 이미 손으로 붙여 넣은 완료 건을 누르면 일정이 하나 더 생긴다. 시험으로 그 건들을 다시 누르지 않는다.

- 스크립트 편집: https://script.google.com/d/1SPHUGnLcX9h9pSqI-otAycUuBnrAAUOeLbsgwr_HKcQs4bLYQgLNj1i9/edit
